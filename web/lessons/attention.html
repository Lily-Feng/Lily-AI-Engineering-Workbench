The rule

Causal: a position can read itself and earlier positions. Bidirectional: every position can read every other position. Prefix: the first three positions read one another; the suffix reads the prefix and its own causal history.

The consequence

A causal mask prevents future-token leakage in next-token training. Blocked scores become −∞ before softmax, so their weights become zero. A prefix position cannot see the generated suffix.

This illustrates self-attention masks, not a complete encoder–decoder architecture. Cross-attention separately reads the encoder’s outputs. Padding masks, which block padding positions, are not shown here.

Try this

Switch the mask above to causal and select the first token. Its output must equal its own V, whatever Q you choose. Only one position is visible, so softmax gives it weight 1.

Why divide by √dₖ?

When query and key components have roughly unit variance, the dot product’s variance grows with dimension. Scaling helps prevent large logits from pushing softmax into a saturated regime.

Why more than one head?

Each head learns different Q/K/V projections and can form a different mixture. Head outputs are concatenated and projected back into the model’s hidden dimension. This toy shows one head before that projection.

Weights describe information routing. They are not, by themselves, a complete explanation of a model’s reasoning. The calculation uses a stable softmax; displayed values are rounded.

03 / SHARED MEMORY

Many questions. Less to remember.

During decoding, cached keys and values save repeated computation. But the cache grows with the sequence—and with every KV head.

Keep 8 query heads. Change KV sharing.

Calculated memory · not a performance benchmark
KV bytes = 2 × batch × tokens × layers × KV heads × head dimension × bytes per element

The factor of 2 counts both keys and values. This example fixes 32 layers, head dimension 128, two-byte elements, and 8 query heads. GiB = bytes / 2³⁰. It assumes a uniform, uncompressed cache and excludes weights, activations, allocator overhead, and replication across devices.

What changes

MHA uses 8 separate KV pairs. Our GQA example uses 2 groups, each sharing one KV pair. MQA uses 1 pair for all 8 query heads. Each query head still computes its own attention weights.

What doesn’t follow

Eight times less KV storage does not guarantee eight times faster generation. Quality and runtime depend on training, kernels, hardware, batching, and the rest of the model. Sharing heads is an architectural choice, not a serving-time switch for an unchanged checkpoint.

04 / CHECK YOURSELF

Make a prediction.

Two small checks before you take the idea into code.

From intuition to implementation

Three things to take with you.

  1. Verify visibility. Check masks for future-token leakage and padding before trusting outputs.
  2. Trace a tiny example. Verify score scaling, softmax normalization, and the weighted sum before scaling up.
  3. Budget the cache. Use the checkpoint’s actual KV-head count, expected context, and concurrency. Measure runtime separately.

The runnable math is in attention.mjs. The local checks cover mask boundaries, normalization, a hand-calculated output, and cache scaling.
