Groundwork is an agent that gives a first-time founder a runnable starter kit:
ordered filings, cited fees, and the tax elections that apply to them. Its evals
were written before its agent loop. Here is what they check, and what a green
suite still does not prove.

<RunMeta />

## Routes, cites, computes. Never advises.

“LLC or S-corp?” has no answer as posed. An LLC is a state legal entity; an
S-corp is a federal tax election made on top of one. Groundwork’s first job is
to untangle the question, not answer it.

**What “correct” means here.** Every fee, form, and deadline rests on quoted
text from an official page that was actually fetched. Steps arrive in an order
that works. A founder outside its scope gets a referral, not a kit. Nothing in
the output recommends, and nothing files.

**What is being evaluated.** The gate that any generated kit must pass, the
bounded repair loop that sends failures back, the audit trail, and retrieval.
These are deterministic, code-graded checks. They run before a model is in the
loop, so every later change has something to be measured against.

## What a green suite doesn’t prove

{passed} of {total} passing is not “correct.” A suite shows what it was written
to catch. These are the things this one was not written to catch.

- **Whether a correct quote is applied correctly.** Nothing checks that a
  correctly quoted page is being applied to the right situation. Human review
  found two errors of exactly this kind; they are shown below.
- **Resistance to hostile sources.** No filing-mill page or injected
  instruction text is in the corpus, so nothing shows the system would resist one.
- **Whether the generated kit runs.** There is no kit compiler yet, so “does the
  kit run” is unmeasured.
- **Breadth.** One hand-authored kit, for one state. Other states are tested only
  negatively: their guidance must not leak into a Texas answer.
- **Model cost and latency.** The agent loop is not built yet. The repair tests
  use stand-in generators, so there is no model call to time or price.

### Caught by human review, not by the suite

| The kit said | The rule actually is |
| --- | --- |
| “Texas LLCs owe an annual franchise tax report even in years when no tax is due.” | For report years 2024 and later the separate No Tax Due Report was discontinued. An entity at or below the threshold files a Public Information Report or Ownership Report. |
| A missed Form 2553 window “costs a full year.” | The IRS documents conditional relief for late elections. The window still matters; the consequence is not automatic. |

Both claims carried valid, verified, official citations. The page was right; its
application was not. See the fixture’s
[REVIEW.md](https://github.com/Lily-Feng/Lily-AI-Engineering-Workbench/blob/main/projects/groundwork/fixtures/golden/tx-solo-consultant/REVIEW.md).

## What I would test next

1. **Poison the corpus on purpose.** Add a filing-mill page and a page carrying
   injected instructions. The kit must neither cite nor obey them.
2. **Turn the human catches into cases.** Have a practitioner grade how quoted
   rules are applied, so both errors above become regression tests instead of
   review notes.
3. **Add a second state.** A California fixture tests cross-jurisdiction
   behaviour directly, rather than only by absence.
4. **Measure the loop once it exists.** Cost, latency, repair rounds, and
   escalation rate per run, read from the audit trail the suite already protects.
